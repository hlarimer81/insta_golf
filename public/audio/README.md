# Background music beds

Four beds live here, written by `npm run beds` (`scripts/make-beds.mjs`). They
are **original compositions generated in this repo**, not licensed recordings —
the account owns them outright, which is the one music arrangement with no
rights question attached at all.

The generator assigns one to each new script by slug hash, so a re-render never
swaps a Reel's music.

## Why not trending audio

Instagram's music library — the trending-sound picker — **cannot be reached
through the Content Publishing API**. It exists only in the native app, so no
API-based tool can attach a track at publish time. Everything this pipeline
posts carries its audio baked into the MP4.

That makes the choice of track a licensing question, not a taste question. This
is a **business account**, which gets a deliberately narrower music catalog than
a creator account because most commercial use needs separate rights. Embedding a
popular commercial song risks territory-based muting, removal, rights-holder
takedowns and account feature restrictions — and a restriction on
`instagram_content_publish` would stop posting entirely, silently.

**So: nothing from the charts, nothing ripped from a Reel, nothing "probably
fine".** Only tracks with an explicit commercial license.

## The generated beds

    npm run beds            # write any that are missing
    npm run beds -- --force # rewrite them all

Four ~38s loops — `fairway-morning`, `range-session`, `back-nine`,
`clubhouse` — each a four-chord progression under a soft arpeggio and a quiet
sub. Deliberately plain: they sit at `volume={0.35}` (`src/BogeyReel.tsx`)
under text-on-screen Reels with no voiceover, so the job is warmth, not
attention. Output is deterministic, so every machine produces identical files.

To change the music, edit the `BEDS` table in `scripts/make-beds.mjs` — each
entry is a name, a seed, a chord progression in MIDI note numbers, and a
low-pass cutoff — then `npm run beds -- --force`. Re-render anything already
scored (`npm run rerender -- --force`), since the audio is baked into the MP4.

## Using licensed tracks instead

If you would rather use a library, these are the ones cleared for commercial
use on a business account:

- **Meta Sound Collection** — free, pre-cleared for use on Meta platforms
- **Epidemic Sound**, **Artlist**, **Uppbeat** — subscription, commercial license

Prefer instrumentals; vocals compete with the on-screen copy. Drop the files in
this folder and they join the pool alongside the generated beds, or set
`BOGEY_AUDIO_TRACKS` to their URLs to use those exclusively.

## Local files vs CI

`public/audio/*` is git-ignored (same as `public/broll/*`), so the tracks
themselves never enter the repo — only this note and the script that writes
them do. That is exactly why generating the beds beats storing them: the
unattended top-up renders **on a GitHub runner** with an empty folder, and it
simply runs `npm run beds` first, the same way b-roll is regenerated by
`scripts/bg.mjs`.

If you supply your own licensed files instead, they are not reproducible that
way — host them and set `BOGEY_AUDIO_TRACKS` to comma-separated **URLs**. The
renderer passes `http(s)` sources straight through (`resolveSrc` in
`src/BogeyReel.tsx`), and that variable wins over anything in this folder.

## Don't move a track a script already uses

`audioSrc` is written into the script JSON at generation time. Renaming or
deleting a track that queued scripts reference makes those renders **fail**, and
an unattended render failure is the silent gap this whole project exists to
prevent. Add new tracks freely; retire old ones only once nothing references
them.
